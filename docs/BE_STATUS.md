## 3. Conflicts to fix (built code vs 25/10 decisions)

1. **BR-07 referral credit** – `ReferralPointSplit` + `VerificationService.SplitHandoverContributions` split one KPI 30/70 based on an `ACCEPTED` `TaskHandover`. New rule: Teller and Sales Officer get credit under **two different KPI items**, identified by the **Refer ID** column of the imported transaction file; missing Refer ID → processor only. The comment in `ReferralPointSplit.cs` still says "credit officer".
2. **Handover approval / SLA** – `HandoverStatus` has `PENDING / ACCEPTED / REJECTED`, `HandoversController` exposes accept, reject and a manager approve / reassign / reject flow, and `HandoverEscalationBackgroundService` escalates overdue requests. New rule: no approval, no SLA (BR-21 deleted).
3. **Manual verification** – `VerificationController` / `review-verify` approve every result. New rule: only work outside the WorkType list is approved manually (SCR-REV-04).
4. **Submission states** – `SubmissionStatus` / `VerificationDecision` lack `MATCHED / NOT_MATCHED / IN_REVIEW`.
5. **Idempotency (BR-08)** – `VerificationService.cs:210` checks for existing `WorkResultItems`; concurrent approvals can still bypass it. Add a unique constraint per Work. A missing active target no longer skips the contribution: approval is rejected with 409 `KPI_TARGET_NOT_ASSIGNED` (`VerifiedResultRecorder`).

Target suggestion engine (as of 2026-11-19): without history the engine now falls back instead of returning `no_history` — tier 1 progressive Q1:Q2:Q3:Q4 = 1:2:3:4, tier 2 by department headcount (quarters follow the branch shape, else 1:2:3:4; the peer-average fallback is gone), tier 3 equal across employees (quarters follow the department shape, else 1:2:3:4). `disabledReason: no_history` remains only when a tier 2/3 KPI has no eligible unit. Verified: 4 new math tests and tiers 1-3 over HTTP on the history path (re-run 2026-11-19 on the dev seed: tiers 1-3 200, bad basis/wrong year 400, unknown anchor 404, no token 401, employee 403); `TargetSuggestionPostgresTests` runs the no-history fallbacks of all three tiers on PostgreSQL.
